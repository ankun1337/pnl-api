### 2. 缓存补充：`as_of=None` 不得钉住（已实现）

**缺数据是可恢复状态**，钉住会让它整天恢复不了。新语义：

| 条目 | 策略 |
|---|---|
| `as_of == 今天` | 钉到 JST 日切 |
| `as_of < 今天` | TTL |
| **`as_of is None`（无 NORMAL 行）** | **TTL** |
| `pin=True` 显式钉住 | 日切（供主数据、日历这类确实取到了数据的条目） |

`DayCache.put` 新增 `pin` 参数；主数据与日历改用 `pin=True`。
测试相应改写：原 `test_as_of_none_treated_as_pinned` 断言的正是被推翻的行为，
已改为 `test_as_of_none_uses_ttl_not_pinned`，另补 `pin` 生效与 `pin` 仍受日切约束两条。

### 3. 交易日历接入（解除"只查不建"，已实现）

新增 `src/pnlapi/calendar.py`：

- 进程内缓存，JST 日切失效，首次请求惰性拉取（窗口：前 30 天 … 后 45 天）；
- 映射 `"1"`/`"2"` → 交易日；`"0"`/`"3"` → 非交易日；
  **未知取值 → `null` + WARN，禁止猜**；
- `meta` 新增 `today_jst` 与 `is_trading_day_today`（不可用时 `null`）；
- 新增只读端点 `GET /v1/calendar?from&to`：透传 `HolDiv` 原值 + `is_trading_day`
  派生值，超出源覆盖范围显式 `not_covered: true`，并回报 `coverage_from/to`；
- 拉取失败一律降级为 `null`，**绝不阻塞盈亏计算**（与名称同源则）；
- 补测试 15 条：0/1/2/3 映射、4 种未知值 `null`+WARN、日切缓存、
  拉取失败/空响应/坏行降级、`not_covered`、meta 字段、端点鉴权与区间校验。

**实测验证**：`/v1/calendar` 覆盖 2026-07-24 … 2026-10-07；
今天（周日）`is_trading_day_today=false`，8/24 周一 `HolDiv=1` 判为交易日。

就绪协议随之简化：消费方不再自己算日历，直接读 `meta.is_trading_day_today`；
`null`（日历不可用）时才退回按星期几粗判。

### 4. 延迟与超时指引（已写入 consumer-api.md 第 8 节）

本机实测（Light 档）：

| 场景 | 耗时 | 构成 |
|---|---|---|
| 冷启动单只 | **4,903 ms** | 一次性主数据（4,444 行）+ 一次性日历 + 1 次行情 |

## 2026-08-23 缓存失效严格按提示词原文（Jack 拍板）

**问题**：提示词 §5 规定缓存「JST 日期翻转即失效」。审计发现的行为后果：
若某代码在当日收盘价发布（约 16:30 JST）**之前**被请求过，旧 as_of 会被
缓存钉到当日午夜——当天 16:30 后的请求也拿不到新价，消费方的
「as_of == 今天才发布」等待协议在这种情况下当天等不到结果。
审计曾建议改为「as_of==今天 当日有效；as_of<今天 只缓存 10 分钟」。

**结论**：Jack 拍板**严格按提示词原文**执行：仅日期翻转失效。

**后果与规避（写入 consumer-api.md）**：消费方要拿当日数字，
当日对任一代码的**首次**请求必须放在 16:30 JST 之后；
若发布前调用过，该代码当天将持续返回旧 as_of，属已知既定行为而非故障。

## 2026-08-23 成本参数 400 与持仓级错误隔离的并存读法

**问题**：§7 说「单个持仓出错不拖垮整个请求」，§7/T4 又说 cost_price 与
cost_total 双给/双缺 → 整体 400。两条存在张力。

**结论**：按「错误层级」区分——**结构性错误**（请求体不满足 schema：
双给/双缺、类型不对）由 pydantic 校验层拦截，整体 400；
