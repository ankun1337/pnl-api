## 2026-08-23 检查点 1 批复（Jack 逐项确认）

### 决策 1：NO_TRADE 判定 —— 批准并追加防御

`O`、`C`、`Vo` 均为 null → `NO_TRADE`（三者实测严格同步，取三个为防御冗余）。

**Jack 追加**：出现**部分 null 的异常行**时不得作为 `latest`，跳过并 WARN。
`latest` 行必须 **`C` 与 `AdjC` 均非 null** 方可进入计算。

> 落地：取价时逐行判定为 `NORMAL` / `NO_TRADE` / `ANOMALOUS` 三态。
> `ANOMALOUS`（既非全 null 又非关键字段齐备）跳过并记 WARN 日志。
> 实测未观察到此形态（5 个样本 null 结构完全一致），此为防御性设计。

### 决策 2：字段映射 —— 批准

| 来源端点 | 源字段 | 目标 |
|---|---|---|
| `/v2/equities/bars/daily` | `C` | `latest_close`（**估值用原始价**） |
| `/v2/equities/bars/daily` | `AdjC` | `pct_change_today` 的分子与分母（**涨跌用复权价**） |
| `/v2/equities/bars/daily` | `Date` | `as_of` |
| `/v2/equities/master` | `CoName` | `name_ja` |
| `/v2/equities/master` | `Code` | 代码双向映射表 |

**Jack 确认**：`CoName` 来源为主数据端点；映射表按来源端点分列（如上）。

### 决策 3：UNKNOWN_CODE 靠主数据兜底 —— 批准方向

空数组无法区分"非交易日 / 不存在代码 / 当日未发布"（实测三者响应相同），
故代码有效性判定必须依赖主数据 code 集合：

- 代码**不在**主数据集合 → `UNKNOWN_CODE`
- 代码**在**集合中但区间内无可用 NORMAL 行 → `NO_RECENT_PRICE`

**Jack 裁定降级行为**：主数据不可用时，错误码**仍用 `NO_RECENT_PRICE`**，
`hint` 注明「主数据不可用，代码有效性未验证」。宁可含糊，不误判。

### 决策 4：代码映射 —— 批准

- 映射**以主数据双向表为准**；
- 「四位 + 补 0」作**降级规则**（主数据不可用时的兜底）；
- 响应中的 `code` **回显调用方传入的原样值**（传 `7203` 就回 `7203`）；
- **去重仅限取数层**：同一代码只向 J-Quants 请求一次；
  **同码多笔持仓在响应中逐行返回**，不合并。

## 2026-08-23 缓存失效严格按提示词原文（Jack 拍板）

**问题**：提示词 §5 规定缓存「JST 日期翻转即失效」。审计发现的行为后果：
若某代码在当日收盘价发布（约 16:30 JST）**之前**被请求过，旧 as_of 会被
缓存钉到当日午夜——当天 16:30 后的请求也拿不到新价，消费方的
「as_of == 今天才发布」等待协议在这种情况下当天等不到结果。
审计曾建议改为「as_of==今天 当日有效；as_of<今天 只缓存 10 分钟」。

**结论**：Jack 拍板**严格按提示词原文**执行：仅日期翻转失效。

**后果与规避（写入 consumer-api.md）**：消费方要拿当日数字，
当日对任一代码的**首次**请求必须放在 16:30 JST 之后；
若发布前调用过，该代码当天将持续返回旧 as_of，属已知既定行为而非故障。

## 2026-08-23 成本参数 400 与持仓级错误隔离的并存读法

**问题**：§7 说「单个持仓出错不拖垮整个请求」，§7/T4 又说 cost_price 与
cost_total 双给/双缺 → 整体 400。两条存在张力。

**结论**：按「错误层级」区分——**结构性错误**（请求体不满足 schema：
双给/双缺、类型不对）由 pydantic 校验层拦截，整体 400；
**运行期错误**（UNKNOWN_CODE、NO_RECENT_PRICE、数值越界）为持仓级错误项，
不拖垮请求。此为对提示词的解释而非修改，T4 与 T5 分别锁两个层级。
