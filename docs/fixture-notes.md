抓取于 2026-08-23 16:17 JST（周日，非交易日）。全部为真实 J-Quants V2 响应，

## 2. NO_TRADE 判定依据（实测，非假设）

无成交行**存在**（不是缺行），其中 **13 个字段同时为 null**：

```
AdjC, AdjH, AdjL, AdjO, AdjVo, C, ExRT, H, L, MktCap, O, Va, Vo
```

仍有值的只有 5 个：`Date`、`Code`、`UL="0"`、`LL="0"`、`AdjFactor=1.0`。

**5 个无成交样本的 null 结构完全一致**（实测校验 `len(set)==1`），
不存在"部分字段为空"的中间形态。

> **判定规则（建议）**：`O is None and C is None and Vo is None` → `NO_TRADE`，
> 否则 `NORMAL`。三者实测严格同步，取三个是防御性冗余。
> **绝不用前收盘价或 0 填充**（红线）。

样本：2026-08-21 全市场 4,443 行中有 **252 行**无成交（约 5.7%）。

## 3. ⚠️ 关键发现：空数组无法区分三种情况

| 场景 | 请求 | 响应 |
|---|---|---|
| 非交易日 | `code=7203&date=2026-08-23`（周日） | `{"data": []}` |
| 不存在的代码 | `code=00000&from=...&to=...` | `{"data": []}` |
| （推定）当日未发布 | 交易日 15:00 JST 前请求当日 | 待补测 |

**三者响应完全相同，HTTP 均为 200。**

这直接决定 `UNKNOWN_CODE` 的实现：

> **空数组本身不能判定代码不存在。** 必须用主数据端点（`/v2/equities/master`）
> 的 code 集合兜底：
> - 代码**不在**主数据中 → `UNKNOWN_CODE`
> - 代码**在**主数据中但区间内无 NORMAL 行 → `NO_RECENT_PRICE`
>
> 提示词 §5 原本只把主数据用于取名称；此处它同时成为 `UNKNOWN_CODE` 判定的必需
> 依赖。这不改变提示词的任何规则，只是明确了主数据拉取失败时的降级行为：
> **名称可以为 null 不阻塞计算，但代码有效性判定会退化**——此时建议返回
> `NO_RECENT_PRICE` 而非 `UNKNOWN_CODE`（宁可含糊也不误判）。

## 4. 主数据 `/v2/equities/master`

14 个字段，无参数请求返回全市场 **4,444 行**，零空值。本项目只用两个：

| 字段 | 用途 |
|---|---|
| `Code` | 5 位代码，用于建立 code 集合与映射 |
| `CoName` | → `name_ja`（样例：`13010` → `極洋`） |

> **休业日行为**（前项目实测）：不传 `date` 参数时，休业日查询返回的是
> **翌营业日**的主数据。本项目只用它取名称与判定代码存在性，此差异无影响。

## 5. 当日收盘价的实测可得时刻（提示词第 6 节要求）

- **实测**：2026-08-21（周五）的收盘价，在 2026-08-22、08-23 均可正常取得，
  字段完整。前项目曾于 2026-08-22（周六）实测取到 08-21 数据。
- **官方文档**：日线约 **16:30 JST** 发布（出处 `https://jpx-jquants.com/ja/spec/data-update`）。
- **【推测，待补测】** 交易日 16:30 JST 之前请求当日数据，形态推定为
  `{"data": []}`（与非交易日一致）。**这是推测，不是实测**——抓样当天是周日，
  无法构造该场景。计划在下一个交易日 15:00 JST 前补测。

> 对实现的影响：**无**。三种空数组场景的处置相同（回退到最近 NORMAL 行），
> 判定代码不需要区分它们。补测只为文档完整性。

## 6. 代码形态注记

- 供应商代码为 **5 位**，普通股末位为 `0`（`1001` → `10010`，示例为虚构代码）
- **可含字母**：实测样本 `131A0`
- 因此：证券代码全程按字符串处理，**禁止转数值、禁止截断**（红线）
- 消费方若传 4 位习惯代码（`7203`），需要在查询前映射到 5 位——
  实现时用主数据建立双向映射
